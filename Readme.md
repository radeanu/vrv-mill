## По ТЗ:

### Левое окно

Отображает все элементы, кроме выбранных, фильтрация элементов по ID, инфинити-скролл, добавление новых элементов, с новыми ID, задается вручную, может быть любым, добавление работает через оптимистичное обновление (на клиенте сразу видно, на сервере задача ждет свою очередь на выполнение, потом клиент запрашивает статус выполнено/нет, если да, так и оставляем, если нет - удаляем), при выборе элемента также используется оптимистичное обновление интерфейса.

### Правое окно

Фильтрация элементов по ID, инфинити-скролл, сортировка элементов с помощью Drag&Drop (работает также для отфильтрованного списка), при Drag&Drop используется такой же подход (оптимистичное обновление).

### Основной flow запросов на сервере

клиент-> запрос к серверу (добавить новый ID) -> дедупликация запроса через idempotency_key -> запись задачи в регистр и в очереди на выполнение -> ответ клиенту -> раз в 10 секунд север берет все задачи из очереди, очищает очередь и выполняет их -> результат выполнения сохраняется в течении 5 минут -> клиент запрашивает статус -> отдаем

### Другие моменты

- Не использовал никакие библиотеки или ИИ
- Фокус на функционал а не на дизайн
- Инфинити-скролл обычный, не виртуальный, знаю что для 1мил строк - надо сделать виртуальный, но в ТЗ такое не было

- Разделил задачи что можно выполнять параллельно (добавить новый ID, выбрать его) и что синхронно (drag&drop)

- Дедупликация происходит на уровне запросов и на уровне очереди задач (когда они повторяются)

- При запросе данных с клиента, сервер кэширует пагинацию на 15 секунд
